Byte-pair encoding

Pick a granularity: how big is one unit of input?

every token will become one vector, and attention costs grow with sequence length — so this choice matters. characters → few vectors to learn but very long sequences; whole words → short sequences but millions of vectors, most barely trained. subwords balance both.

Grow a vocabulary: merge the most frequent pair, repeat

BPE builds the token list from data, not from a dictionary: count every adjacent pair in the training text, fuse the most frequent pair into a new token, repeat. fragments that recur often enough earn their own ID — and later, their own vector.

learned merges = the vocabulary being born

run all merges — est emerges as a token because English reuses it. 50,000 merges on the whole internet ≈ GPT-2's real vocabulary.

After this step, the text is gone

what leaves this stage is only a sequence of integer IDs. each ID's sole job is to select one row of the embedding table in chapter 2 — the letters themselves never enter the network, which is why models struggle to count the r's in "strawberry".

the bottom row is all the model receives — spelling and digit-math must be reconstructed from opaque chunk IDs.

Vocabulary size trades sequence length for table size

more merges → longer tokens → fewer vectors flowing through the network per sentence (cheaper attention), but a bigger embedding table to learn, since every ID needs its own row of 12,288 numbers.
