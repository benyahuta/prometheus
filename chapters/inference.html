The KV cache

The live demo showed the loop: predict, sample, append, repeat. Taken literally, that loop re-reads the entire context every token — most of it redundantly. The trick that makes real chatbots fast is embarrassingly simple: remember your keys and values.

Two phases of a reply

Prefill — your whole prompt is processed at once, in parallel (this is the pause before the first word appears). Decode — then tokens come out one at a time, each requiring a full pass through the model. The two phases feel different because they are: prefill is one big matrix multiply; decode is a loop.

The redundancy

In the attention chapter, each token computed a key and value. Here's the thing: token 3's key never changes. When you're generating token 50, tokens 1–49 have exactly the same keys and values they had last step — causal masking guarantees nothing behind you ever changes. Recomputing them every step is pure waste. So: compute each token's K and V once, and keep them.

With the cache, each new token costs one new K,V row plus one read over the cache — linear work per token. Without it, step n recomputes all n rows, and a whole reply costs quadratically more. The gap on the counters above is after seven tokens; imagine it at seven thousand.

What the cache costs instead: memory

Nothing is free. The cache holds a K and V vector per token, per layer, per head — for a big model, that's on the order of a megabyte of GPU memory per token of context. This is the physical reason context windows are finite, long chats get slow and expensive, and serving providers care so much about memory. When people say "the context window is full," they mean: the cache is full.

Why the loop still feels fast

Three tricks stack on top of the cache. Batching — the GPU generates for many users in one matrix multiply; your tokens ride along with strangers'. Speculative decoding — a small, cheap model drafts a few tokens ahead, and the big model verifies the whole draft in a single pass (checking is parallel; guessing is not). And quantization — storing weights and cache in fewer bits, trading a sliver of accuracy for a big cut in memory traffic. Between them, the loop that looks so laborious in the demo runs at tens to hundreds of tokens per second.
