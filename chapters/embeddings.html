The embedding matrix

"Each token becomes a vector" is really just a table lookup — but the table is learned, and there's a subtle problem to solve: attention has no idea what order the words came in.

One giant lookup table

The embedding matrix WE has one row per vocabulary entry and one column per dimension — for GPT-3 that's 50,257 × 12,288, about 617 million parameters before any actual "thinking" machinery. Embedding a token means: take its ID, copy out that row. Click a token:

These numbers start random and are shaped entirely by training. Nobody designs "dimension 3 means furriness" — but directions with meaning (gender, tense, sentiment…) emerge, which is why the vector arithmetic on the main page works.

The order problem

Here's the catch: attention treats its input as a set. Swap the words of "dog bites man" around and every query–key dot product is identical — "man bites dog" would get exactly the same attention scores. Word order has to be injected explicitly, by adding a position vector to each token vector:

inputi = WE[tokeni] + PE(i)

Positional encoding, drawn

The classic recipe uses sine waves: each dimension of PE oscillates as you move along the sequence, and each pair of dimensions oscillates slower than the last — fast counters for nearby positions, slow ones for far apart. Any position gets a unique fingerprint. Drag the slider:

Modern models mostly use variations on this theme — learned positions, or rotary encodings (RoPE) that rotate the query/key vectors by a position-dependent angle — but the job is identical: make "dog bites man" and "man bites dog" look different.
