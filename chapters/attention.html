Queries, Keys & Values

the word bat starts with the exact same vector in “the bat left the cave” and “he dropped the bat” — chapter 2's embeddings know the word, not the sentence. attention is the machinery that lets the neighbours fix that. below: “the robot ate apples”, computed for real — scroll, and the multiplications happen in front of you.

Q — query
the question this word asks the others — “anyone here my subject?”
K — key
its standing answer to such questions — “I'm a noun, doing the action”
V — value
the nudge it contributes when question and answer match
Attention(Q, K, V) = softmax QKT√dk V

① the input X: one vector per token, and none of them know each other yet

each row is one token's vector — everything that token currently "knows". right now ate's vector contains nothing about robot. this whole page is one mechanism for copying information between these rows.

X  (4 tokens × 4 dims)
one row per token — dense and messy, like real embeddings

4 dims is for legibility — GPT-3's rows are 12,288 numbers long. same picture, ~3,000× wider.

② each vector is projected into three roles: Q = X·WQ

multiplying by a learned matrix makes a smaller vector that keeps only one kind of information from the embedding. think of grammar: an adjective's key is shaped to answer a noun's “anything describing me just before?”, and here ate's query asks “who did this?” — Q is the question a token asks, K is its standing answer, V is the nudge it will contribute if the two line up. (in GPT-3 these projections drop each 12,288-number vector into a 128-dimensional question-and-answer space.)

WQ, WK, WV are the learned weights — training tunes these numbers; everything else on this page is pure arithmetic.

③ score every pair: which tokens should copy from which?

the dot product Qi·Kj measures how well token j's answer fits token i's question — when the two vectors point the same way, the score is large and we say i attends to j. a high score is a decision being made: information will flow from j into i two steps from now.

masked cells become −∞, so softmax sends them to exactly 0

read row ate as: "how much should ate's vector absorb from each other token?" the spike at column robot means the model decided who did the eating is the information this verb is missing. why the mask? training predicts the next token at every position of the sentence at once — one sentence, many little exams — so no word may take hints from words that come after it, or the exam is rigged. (÷√dk just keeps scores in a range softmax handles well.)

④ softmax turns each row into a mixing recipe

each row of A is now the recipe for rebuilding one token's vector: "to update ate, take 61% from robot, 24% from itself, 15% from the…". softmax guarantees the parts are positive and sum to 1, so the next step is a legitimate weighted average.

A = softmax(S)
each row sums to 100% · −∞ becomes exactly 0

⑤ the information actually moves: O = A·V

this is the step where vectors change hands. each token's output row is the weighted average of everyone's V vectors, using its recipe from step ④ — so ate's new vector now literally contains a piece of robot's content. information has crossed between positions for the first time.

⑥ shape the mix into an edit: ΔX = O·WO

the blended vectors live in the head's small 3-dim space and can't be added to the 4-dim embeddings yet. WO maps them back to full width — and what comes out is, for each token, an edit vector ΔX: "given what i just gathered from the other tokens, move my embedding this way."

⑦ the edit is added onto each vector: X′ = X + ΔX

each token's vector is nudged, not rebuilt — picture the 3-D map from chapter 2: adding ΔX slides the point through that space, from generic ate toward ate-by-a-robot. the old vector still encodes "a verb, past tense" underneath; the context is layered on top. this add-never-replace habit is the residual stream, and it's why 96 layers of edits can stack without erasing each other. by the last word of a long story, enough edits have piled up that one vector can carry whatever the next word hinges on — even a clue from the first page.

⑧ many heads propose different nudges at once

each head runs this entire page independently, with its own WQ, WK, WV — one asks grammar questions (subject→verb), another tracks each token's left neighbour, another watches the sentence start. every head proposes its own ΔX, and the proposals simply add together onto the same vectors.

MultiHead(X) = concat(head1, …, headh) · WO

in practice the per-head WO pieces are stapled side-by-side into one big output matrix for the whole block. the scale of this in GPT-3: 96 heads per layer × 96 layers, each with its own 128-dim question-and-answer space — attention alone is ~58 billion of the 175 billion parameters, all running as one batched matrix multiply.
